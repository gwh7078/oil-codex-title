# oil-codex-title

管理后台标题命名与 7 天闲置归档。自动逻辑由 Stop Hook 执行；归档只按时间判断，不调用模型判断任务是否完成。

## 定位入口

执行本 Skill 内的 `scripts/run.py`。该入口会定位插件的后台程序，不写死缓存版本。本文件向上两级是插件根目录。

下面的 `<入口>` 表示该脚本的绝对路径，`<话题 ID>` 来自用户引用或宿主读取结果，不能猜测。

## 检查与配置

Windows 下将示例的 `python3` 换成 `py -3`，需要已安装 Python Launcher。Windows 启动与 CLI 路径说明见插件根目录 `docs/Windows安装与验证.md`。

1. 执行 `python3 <入口> doctor`，检查 Python、Codex 路径和 App Server。
2. 用户提供话题时，追加 `--thread <话题 ID>` 验证读取兼容性。
3. 需要配置模型时，执行 `configure --model <模型 ID> --service-tier fast` 或 `--service-tier standard`；修正可执行文件使用 `configure --codex-bin <路径>`。模型和档位应来自用户选择或当前可用列表，不猜模型名。默认 Luna Fast，Spark 使用 standard。
4. 调整自动命名频率时，执行 `trigger-configure --first-trigger-turns <首次有效轮数> --trigger-interval-turns <后续间隔轮数>`。两项都必须是 1～1000 的整数；默认分别为 1 和 5，对应第 1、6、11、16……个有效轮次。
5. 执行 `trigger-status` 查看标题触发配置、计数记录以及自动归档配置和最近扫描状态。
6. 执行 `archive-scan` 可不等待 6 小时间隔，立即做一次闲置归档扫描。
7. 安装及信任步骤见插件根目录 `README.md`。只通过官方插件安装和 Hook 信任入口操作，不修改信任数据库，也不绕过信任机制。

Hook 安装、启用、信任和实际成功运行是不同状态。`doctor` 成功不能证明 Hook 已自动触发。

## 标题规则

标题采用「类别 emoji + 对象｜当前具体任务/问题」。

- 工作区通常就是项目名，默认不要在标题中重复项目名。
- 左侧对象优先使用模块、功能、页面、服务、插件、Skill、模型或内容主题；对象准确后保持稳定。
- 右侧写具体任务/问题，避免只写“优化”“开发”“完善”“处理问题”。
- “继续”“测试一下”“commit”“push”“截图”“解释术语”等通常只是执行步骤，不单独替换主线标题。
- 主对象或主任务实质变化时才 rename；现有标题仍准确时优先 keep。
- 用户主要语言改变时可做一次语言迁移，技术名词和产品名保留原文。

详细规则在插件根目录 `prompts/naming.md`。

## 自动命名触发

- 只有原命名逻辑本来会进入模型评估的有效轮次才计数；`disabled`、`archived`、`locked`、`manual_title`、`unchanged` 等跳过状态不计数。
- 同一 Stop Hook 重复触发不重复计数。
- 真正触发命名模型时，默认携带最近 5 个有效轮次，并单独保留首轮 `original_goal`；不是只提交当前触发轮次。
- 手动 `rename` / `--apply` 不受自动触发轮次限制，用户明确请求时立即执行。

`throttled` 表示当前轮次本来可以进入模型评估，但尚未达到首次或后续触发阈值；这是正常节流。`throttled_duplicate` 表示同一 Stop Hook 已计数过，不会再次增加计数。

## 改名与预览

1. 执行 `python3 <入口> rename <话题 ID>`，由独立模型生成预览。
2. 用户已经要求改名时，直接执行同一命令并追加 `--apply`；预览请求停在候选结果。
3. `renamed` 表示标题元数据已写入并读回核验；`kept` 或 `unchanged` 表示保留。
4. 返回实际标题和状态，不把候选当作已经生效的标题。

`locked` 或 `manual_title` 表示标题受保护。只有用户要求恢复自动命名或覆盖手动标题时，才执行 `unlock <话题 ID>` 后重试。

`stale_result` 或 `outdated_event` 表示对话已更新，本次候选已丢弃。用户要立即更新时可重新执行，自动入口等待后续有效轮次。

`ambiguous_title` 表示候选仍与已记录任务重名，本次保留原名。可以请用户补充具体对象，再重试。

如果置顶列表仍显示旧标题，先读回真实标题，再使用宿主提供的 `set_thread_title` 同步该标题并核对列表。后台 Hook 没有经过验证的桌面刷新通道，不得直接修改桌面私有状态文件。

## 7 天闲置归档

默认开启，规则固定而简单：最后一个已完成对话轮次距当前时间达到 7 天后，自动归档。

- 计时依据是最后一个已完成轮次的 `completedAt`，没有时使用 `startedAt`；标题或元数据更新不算活跃。
- 任意新的对话轮次都会自然更新最后活跃时间，重新计算 7 天。
- 当前触发 Hook 的话题必须跳过。
- 子 Agent、临时话题和非空闲话题必须跳过。
- 归档前必须再次读取目标话题；如果轮次 ID 或时间已改变，本次不归档。
- 实际归档只调用官方 App Server `thread/archive`；不得直接修改数据库或桌面私有状态。
- 不调用模型判断完成度、待办或价值，不恢复旧的复杂归档工作流。
- Stop Hook 最多每 6 小时扫描一次；它不是独立系统定时器。Codex 长时间未运行时，在下一次 Stop Hook 补做扫描。

用户要求立即整理时执行 `python3 <入口> archive-scan`。如果返回 `scanned`，报告实际归档数量；如果没有符合条件的话题，归档数量为 0。普通自动扫描返回 `throttled` 只是表示距离上次扫描不足 6 小时。

## 暂停与保护

- `pause`：暂停自动命名；不会关闭 7 天闲置归档。
- `resume`：恢复后续轮次的自动命名。
- `lock <话题 ID>`：固定该话题当前标题，只影响标题命名，不作为归档保护标记。
- `unlock <话题 ID>`：重新允许该话题自动命名。
- `status`：显示命名配置位置、启用状态和已记录话题数量。
- `trigger-status`：显示自动触发轮次与自动归档状态。

第一次接触话题时，插件无法判断现有标题是否来自用户手动设置。对需永久保留的历史标题使用 `lock` 只能保护标题；当前轻量归档没有额外的永久排除列表。

## 失败处理

标题命名失败时保留原标题。单个归档失败应记录错误并继续其他候选，不把失败当作成功；下一次扫描可再次判断。先处理 `doctor` 报告的兼容性或登录问题，再重试。

不要恢复原话题来发送管理指令，不直接修改数据库或对话文件，不让主 Agent 接管后台循环。

后台日志仅记录状态、标题、用量及归档计数，不保留完整对话。命名状态位于原 thread JSON；触发计数使用数据目录下 `trigger-counters/<thread_id>.json` 的轻量本地 JSON；归档仅记录最近扫描时间和数量，不需要数据库。
