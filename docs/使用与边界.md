# oil-codex-title

让 Codex 侧边栏的话题名称跟上实际工作内容，并用确定性的时间规则自动整理长期不活跃的话题。本 fork 不恢复旧的模型归档判断工作流。

## 核心行为

- Stop Hook 每轮结束后都会运行，但只有达到配置的有效轮次时才调用命名模型。
- 默认首次第 1 个有效轮次触发，之后每 5 个新的有效轮次再次触发，即第 1、6、11、16……轮。
- 被原命名逻辑跳过的轮次不计数；重复 Stop Hook 不重复计数。
- 真正触发模型时，默认使用首轮 `original_goal` + 最近 5 个有效轮次，而不是只看当前一轮。
- 手动预览或手动重命名不受自动触发间隔限制。
- 闲置归档默认开启：最后一个已完成对话轮次达到 7 天无更新后归档，不调用模型。
- 归档扫描最多每 6 小时一次，并在真正归档前重新读取目标话题。

## 安装

这是本地 Codex 插件，需要 Python 3.10+、已登录且兼容当前话题存储及 `thread/archive` 的 Codex CLI。

可以直接把下面这段话发给 Codex：

```text
帮我查找 GitHub 仓库 gwh7078/oil-codex-title 的 feature/configurable-title-trigger 分支，下载并安装完整插件。开启话题自动命名，并启用连续 7 天无新对话自动归档。安装后运行 doctor、trigger-status 和一次 archive-scan 验证；不要恢复旧的模型归档判断逻辑。如果需要我在界面中信任 Stop Hook，请告诉我具体操作。
```

安装插件本身不等于 Hook 已启用和信任。实际自动触发需要在 Codex Hook 管理入口确认。

## 命名方式

标题采用：

**类别 emoji + 对象｜当前具体任务/问题**

例如：

- `🧩 Story 详情页｜实现完成度展示`
- `🧩 Onboarding｜修复 Life Stage 路由`
- `🧩 Closeout｜精简总结 Schema`
- `🧩 语音访谈｜支持动态首问`

规则重点：

1. 工作区通常就是项目名，默认不在标题里重复项目名。
2. 左侧对象优先使用模块、功能、页面、服务、插件、Skill、模型或内容主题。
3. 对象一旦准确，保持稳定，不因细节和进度变化换同义词。
4. 右侧写具体任务/问题，避免只写“优化”“开发”“完善”“处理问题”。
5. “继续”“测试一下”“commit”“push”“截图”等通常只是执行步骤，不单独替换主线。
6. 主对象或主任务实质变化时才重新命名；现有标题仍准确时优先 keep。
7. 标题跟随近期用户实质需求的主要语言，技术名词和产品名保留原文。

详细规则见 [命名与回归规范](命名与回归规范.md) 和 `prompts/naming.md`。

## 触发配置

默认：

```json
{
  "first_trigger_turns": 1,
  "trigger_interval_turns": 5,
  "auto_archive_enabled": true,
  "auto_archive_days": 7
}
```

配置标题触发：

```sh
python3 scripts/oil_codex_title_trigger.py configure \
  --first-trigger-turns 1 \
  --trigger-interval-turns 5
```

查看标题与归档状态：

```sh
python3 scripts/oil_codex_title_trigger.py status
```

设置标题触发为 `1 / 1` 时，频率接近原版的每个有效轮次都评估。

触发计数保存在 `$CODEX_HOME/oil-codex-title/trigger-counters/` 下按 thread 独立的轻量 JSON 文件，不需要数据库。

## 7 天闲置归档

归档依据只有最后对话活动时间：

- 取最后一个已完成轮次的 `completedAt`，缺失时使用 `startedAt`。
- 达到 7 天未出现新轮次时进入归档候选。
- 标题、配置或其他元数据变化不重置计时。
- 当前 Hook 所在话题、子 Agent、临时话题、非空闲话题跳过。
- 归档前再次读取；只要最后轮次 ID 或时间改变，本次立即取消。
- 调用官方 App Server `thread/archive`，不直接修改对话数据库或桌面私有状态。
- 不判断任务是否完成、是否仍有待办，也不调用归档模型。

自动扫描依赖 Stop Hook，不是独立系统定时任务。Codex 长时间完全未运行时，会在下一次 Stop Hook 补做。

需要立即扫描：

```sh
python3 scripts/oil_codex_title_trigger.py archive-scan
```

## 日常控制

Windows 使用 `py -3` 替代 `python3`。

```sh
python3 scripts/oil_codex_title.py doctor
python3 scripts/oil_codex_title.py status
python3 scripts/oil_codex_title.py rename <话题ID>
python3 scripts/oil_codex_title.py rename <话题ID> --apply
python3 scripts/oil_codex_title.py lock <话题ID>
python3 scripts/oil_codex_title.py unlock <话题ID>
python3 scripts/oil_codex_title.py pause
python3 scripts/oil_codex_title.py resume
python3 scripts/oil_codex_title_trigger.py archive-scan
```

`rename` 默认只预览；`--apply` 才写入标题并读回核验。`pause` 只暂停自动命名，不关闭 7 天归档。

## 模型与用量

默认使用 GPT-5.6 Luna Fast。命名消耗当前 Codex 账号的模型额度；闲置归档不调用模型。

触发节流只减少调用频率，不改变单次命名的上下文策略。默认每次评估仍会读取首轮目标和最近 5 个有效轮次，因此可以识别“按这个做”“继续”等依赖前文的表达。

同一轮如果候选标题与同工作目录的已记录标题冲突，原命名逻辑可能额外调用一次模型做区分。这个重试属于同一次触发，不额外增加轮次计数。

## 状态保护

标题命名以下情况会保留原标题或跳过模型：

- 自动命名暂停；
- thread 已归档；
- 标题已锁定；
- 检测到外部手工改名；
- 当前内容与上次评估相同；
- Stop 事件过期、未完成或状态不稳定。

同一话题使用进程锁。模型运行期间如果用户又发了新消息、改名、暂停或锁定，旧结果会被丢弃，避免覆盖新状态。

标题 `lock` 只保护标题，不是归档永久排除标记。当前轻量归档有意不增加额外保护名单和复杂状态。

## 数据与隐私边界

配置、每话题状态、触发计数、归档扫描状态和简短日志默认位于 `$CODEX_HOME/oil-codex-title`；未设置 `CODEX_HOME` 时使用 `~/.codex/oil-codex-title`。

插件不保存完整对话或命名提示词。持久日志只记录状态、候选标题、简短理由、用量和归档数量。

后台 Hook 只返回空 JSON，不向原任务追加管理消息。

## 兼容性

- macOS：已做真实标题链路验证；新增归档需在已安装版本做一次真实归档验收。
- Windows / Linux：原有程序级自动化验证已覆盖标题链路；新增归档仍需实际环境验收。
- 云端和 ChatGPT Work：不支持本地话题适配器。
- 插件只影响 Codex thread，不修改普通 ChatGPT Chat。
- 部分桌面版本的置顶列表可能缓存旧标题；元数据写入成功不等于所有 UI 位置立即刷新。
