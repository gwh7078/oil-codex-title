# 发布验收

当前状态：预览版。这个 fork 保留 Codex 标题自动命名，并新增一条确定性的轻量归档规则：最后一次对话活动达到 7 天后自动归档；不使用模型做归档判断。

## 当前核心能力

- Stop Hook 后台命名，不向原任务增加消息。
- 默认首次第 1 个有效轮次触发，之后每 5 个新的有效轮次再次评估，即第 1、6、11、16……轮。
- 原有 skip 状态不计数；同一 Stop Hook 重复触发不重复计数。
- 真正触发模型时使用首轮 `original_goal` + 最近 5 个有效轮次，不只看当前一轮。
- 手动预览和手动改名不受自动触发间隔限制。
- 同一轮标题冲突时允许原命名逻辑内部重试，但不会因此重复增加轮次计数。
- 闲置归档默认 7 天，最多每 6 小时扫描一次，不调用模型。
- 归档前二次读取目标话题；最后轮次发生变化时取消本次归档。
- 当前话题、子 Agent、临时话题和非空闲话题不自动归档。
- 实际归档通过官方 App Server `thread/archive`，不直接修改数据库或桌面私有状态。

## 当前命名规则

标题采用「类别 emoji + 对象｜当前具体任务/问题」。

重点规则：

- 工作区通常承担项目名，默认不机械重复项目名。
- 左侧对象优先稳定：模块、功能、页面、服务、插件、Skill、模型或内容主题。
- 右侧写具体任务/问题，不只写“优化”“开发”“完善”“处理问题”。
- 测试、commit、push、继续执行、截图等通常只是现有主线步骤，不单独替换标题。
- 主对象或主任务实质变化时才 rename；现有标题仍准确时优先 keep。
- 标题语言跟随近期用户实质需求的主要语言，技术名词保留原文。

典型示例：

- `🧩 Story 详情页｜实现完成度展示`
- `🧩 Onboarding｜修复 Life Stage 路由`
- `🧩 Closeout｜精简总结 Schema`
- `🧩 标题触发｜首轮与间隔配置`

## 已验证的程序边界

现有命名链路已经覆盖：

- 标题结构校验；
- 用户锁定与外部改名保护；
- Stop 事件过期和未完成状态；
- 模型运行期间出现新对话后的 stale result 丢弃；
- 同工作目录的标题冲突重试；
- Unicode 与跨平台文件锁相关边界；
- 模型结果写入后读回核验。

触发策略测试覆盖：

- 默认 1 / 5 触发序列；
- 自定义首次触发和后续间隔；
- 重复 turn 不重复计数；
- 已有旧 thread 按后续 interval 迁移；
- 非法配置值拒绝；
- 同一轮内部 generator 重试允许执行，但后续重复 Hook 仍被阻断。

本次 7 天归档新增聚焦测试覆盖：

- 只归档超过阈值的顶层普通话题，并跳过当前话题与子 Agent；
- 扫描后、实际归档前出现新活动时取消归档；
- 常规 Stop Hook 扫描在 6 小时间隔内被节流。

这些新增测试已在隔离 Python 环境执行通过。当前 GitHub 仓库未产生本次推送对应的 Actions 运行，因此不能把这次结果表述为完整跨平台 CI。

## 真实桌面仍需验收的部分

隔离环境不能替代真实 Codex 桌面端。最终发布前仍应在实际本地环境检查：

1. 安装并启用本 fork；
2. 信任 Stop Hook；
3. 新建 thread，首轮确认发生一次标题评估；
4. 连续有效对话，确认后续达到配置间隔才再次评估；
5. 执行 `trigger-status`，确认 `auto_archive.enabled=true`、`days=7`；
6. 执行一次 `archive-scan`，确认 App Server 能实际归档符合条件的话题；
7. 对一个刚重新活跃的话题确认二次读取会阻止误归档；
8. 检查标题元数据实际写入并可读回。

## 已知桌面显示限制

当前某些 macOS 桌面版本中，独立 App Server 的 `thread/name/set` 可以更新持久标题，但置顶列表可能继续使用旧缓存。通过主 Agent 的宿主标题同步能力可以刷新显示。

因此：

- `renamed` 表示标题元数据写入成功并读回；
- 不代表所有桌面 UI 位置会立即刷新；
- 不修改桌面私有状态文件来绕过缓存。

## 开发检查

小改优先跑直接相关测试：

```sh
python3 -m unittest tests.test_trigger_policy -v
python3 -m unittest tests.test_inactive_archive -v
```

需要完整程序检查时：

```sh
python3 -m unittest discover -s tests -v
```

模型命名质量测试另行运行，避免普通代码修改反复消耗模型额度：

```sh
python3 scripts/evaluate_naming.py
python3 scripts/evaluate_naming.py --live
```

## 发布原则

不能把程序测试、CLI 连接、模型调用、真实归档和桌面 UI 刷新视为同一个层级的验收。发布说明应分别说明证据边界。

当前 fork 的目标保持简单：**标题自动命名 + 可配置触发频率 + 7 天确定性闲置归档**。不恢复模型归档判断、复杂待办识别或独立定时服务。
